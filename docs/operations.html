Overview

Operations

Run the tool

Install the declared dependencies from file-parser-agent/. Its package.json declares mammoth, pdf-parse, word-extractor, and xlsx. Run the entry point from that directory with a JSON object on standard input.

cd file-parser-agent
printf '%s' '{"file":"tests/fixtures/sample.txt"}' | WORKSPACE_PATH="$PWD" node src/tools/process-documents.mjs

The tool also accepts the object beneath input, arguments, or args. The public MCP descriptor requires file and exposes optional type. The process accepts fileType as an alias and an options object for direct invocation.

Paths and output limits

For the command, relative paths resolve from WORKSPACE_PATH when set, otherwise from the process working directory. A library caller can supply options.workspaceRoot, which takes precedence over that environment variable. The command does not pass a workspace-root option to the loader. The example sets WORKSPACE_PATH to its working directory so an inherited value cannot redirect the fixture lookup. Absolute paths are retained. The caller and runtime determine filesystem access; this resolver does not enforce a sandbox boundary.

maxPreviewChars is clamped to at least 500 and maps to the preview limit. tableSampleRows is clamped to at least one whole row. includeRaw selects the formatter's raw-text section. Unsupported or unreadable documents can produce warnings; fatal input and formatting errors exit with status 1.

Verification

npm test in file-parser-agent/ selects node --test tests/**/*.test.mjs. Unit checks cover path resolution, document loading, Markdown formatting, stdin parsing, and the separate LLM helper. Integration tests exercise the command through standard input and inspect Markdown output. These are parser checks, separate from Ploinky's deployment acceptance runner.
